## 5. 완료를 막는 구체적 근거

1. **지도 스키마:** 현재 패키지 매핑으로 StaticMeshComponent 121건과 MaterialInstanceDynamic 64건에서 오류가 발생하고 AionWorldSettings는 64바이트가 남는다. 엄격한 해독 검사는 의도대로 실패한다. 필드 개수를 임시로 바꾼 실험만으로 월드 좌표를 확정할 수 없다. 대응하는 검증된 매핑 또는 독립적인 월드-이미지 기준점이 필요하다. 증거: `operations/map-package-audit.json`, `operations/tile-layout-research.json`.
2. **제작 확률·비용:** CraftRecipeRate의 `Unknown0_Byte`/`Unknown1_Int`와 일부 CraftRecipe 필드의 의미가 미확인이다. 숫자가 존재한다는 이유로 확률 단위·수수료를 추정하면 잘못된 계산을 제공한다. 실제 게임 결과 또는 신뢰할 수 있는 필드 명세와의 대조가 필요하다.
3. **전투 데이터:** 학습 비용과 일부 보드 효과의 일치는 전체 스킬 효과·배율·스탯 연산의 정확성을 증명하지 않는다. 기존 정상 작동 카탈로그를 불완전한 공식 필드로 덮어쓰지 않았다.
4. **실시간 서비스:** 현재 사용하는 공식 EU 서버 목록 API에서 46개 레코드의 필드는 raceId/serverId/serverName/serverShortName이다. 이를 온라인 상태로 간주하지 않는다. 참고 사이트의 [서버 상태](https://aion2.gaming.tools/server-status)와 [티어 분석](https://aion2.gaming.tools/tier-list)은 별도의 실시간 상태·리더보드 표본 기능이다. 해당 사이트의 수집 데이터를 복제하지 않았으며, 우리 쪽 공식 수집·검증 체계는 아직 없다.

위 문제는 새로운 허가를 받는 것만으로 해결되지 않는다. 이미 승인된 범위에서 조사했지만, 정확성의 근거가 없는 항목까지 완료라고 표시할 수 없다. 후속 구현도 남아 있으므로 전체 프로젝트가 끝났다고 판단하지 않는다.

## 6. 리스크와 다음 작업

기존 저장 데이터와 원본 파일을 보존했다. 클라이언트 빌드 스냅샷과 운영 서버는 다를 수 있고, 일부 이름은 미확인이다. 프런트엔드 청크 크기 경고가 남아 있다.

다음 완료 관문은 지도 패키지의 정확한 필드 매핑, 제작 확률/비용·전투 수치의 의미 검증, 공식 실시간 상태/랭킹 수집 경로 확보다. 확보 후 각각 독립적인 테스트와 운영 수용 검사를 거쳐야 하며, 조회 목록 추가만으로 이를 대체하지 않는다.

## 7. 지도 후속 진단 — 2026-10-16

현재 매핑의 상속 구조를 직접 조회한 결과, MaterialInstanceDynamic은 총 21개 슬롯(0~20)인데 지도 해독 로그에서는 24번을 64회 요청한다. StaticMeshComponent 136번은 `Unknown` 타입으로 121회 요청된다. AionWorldSettings의 요청 인덱스는 존재하므로, 앞서 확인한 64바이트 미소비 문제는 인덱스 존재 여부만으로 판별할 수 없다.

이를 재현하는 `audit-mapping-coverage.py`와 연구 도구용 조회 패치를 추가했다. 입력 해시·상속 구조·오류 건수는 `operations/mapping-coverage-audit.json`에 기록했다. 실제 입력은 예상대로 종료 코드 1로 거부되며, Python 테스트 57개가 통과했다. 정확한 대체 필드 의미는 아직 확인되지 않았고, 서비스 좌표나 마커를 변경하지 않았다. 전체 완료 판정은 계속 보류한다.

연구 도구 자체 테스트 54개도 통과했다. 이번에는 서비스 런타임 변경이 없어 프런트엔드 빌드·브라우저 검사는 재실행하지 않았다.

1. **수행한 작업 요약**: 직업별 빌드 보관·복구·내보내기, 아이템↔제작법 양방향 이동, 공식 Steam 전체 접속자 수 조회를 추가했다. 전체 사이트 완료 판정은 여전히 보류다.
2. **변경 파일**: 프런트 `app/build-library.tsx`, `lib/build-library.ts`, `app/steam-activity.tsx`, `app/client-database.tsx`, `app/page.tsx`; 백엔드 `SteamActivityService.java`, `SteamActivityController.java`; 각 단위/브라우저 테스트 및 프로젝트 문서.
3. **핵심 변경**: 보관함은 별도 저장 키로 20개/직업을 보관하고, 적용 전 복구본 저장에 성공해야만 계획을 변경한다. 손상·용량 초과·동시 탭 충돌 시 기존 데이터 유지. 제작법은 공식 클라이언트 인덱스 ID로 연결한다. Steam은 app 3393110 공식 API만 사용하고 확인 시각·갱신 실패를 표시한다.
4. **실행한 테스트**: 프런트 17묶음, 타입 검사, 운영 빌드, 백엔드 19개, Python 작업 도구 57개 통과. 신규 브라우저 검사에서 내보내기·새로고침 복구·동시 탭·저장 실패, 제작 참조 이동, Steam 정상/오류/잘못된 응답/이전 값/0명/복구/모바일/저장 보존 통과. 기존 8직업·데이터베이스 로컬 회귀 검사 통과.
5. **실패 및 미확인**: Mockito 중첩 설정으로 2개 테스트가 처음 실패하여 응답 생성 순서를 수정한 뒤 전체 통과했다. 레거시 운영 스크립트가 systemd 프로세스를 인식하지 못해 정식 서비스 재시작으로 수정했다. 서버별 혼잡도, 전투 스킬 배율 전체, 제작 확률·수수료, 지도 월드 투영은 여전히 미확인이다. 공식 아이템 API 후보는 실제 요청에서 404를 반환해 채택하지 않았다.
6. **리스크**: 기존 500 kB 초과 청크 경고 유지. 보관함은 브라우저 로컬 저장이며 데이터 삭제에 대비해 JSON 내보내기가 필요하다. Steam/API 및 WSL 호스트 가동에 의존한다. 전체 접속자 수는 개별 서버 가동 상태를 의미하지 않는다.
