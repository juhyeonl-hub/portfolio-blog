# 게임 데이터 변경 검토 절차

기존 6시간 확인 작업은 계속 사용한다. 프런트엔드 자동 배포나 새 예약 작업은 추가하지 않는다. 이름·아이콘 외에 보드 비용·효과·해금·배치·연결 구조가 달라지면 기존 계산 데이터를 유지하고 검토 상태를 표시한다. 새 스킬과 삭제된 노드도 자동 적용하지 않는다.

공개 카탈로그 응답의 boardRefresh는 최근 확인, 최근 정상 확인과 고정된 실패 분류만 담는다. 원본 응답·예외 전문·토큰을 공개하지 않는다. 상태는 기존 shadowcraft_catalogs 테이블의 board-status-직업 키로 보존해 서버 재시작 뒤에도 확인할 수 있다. 별도 스키마 변경은 없다.

검토는 다음 순서로 진행한다.

1. 해당 직업의 skillDataCheck와 boardDataCheck, 실패 분류, 원본의 실제 변경 내용을 확인한다. 조회 실패는 내용 변경과 구분한다.
2. 공식 클라이언트·공식 안내 또는 검증 가능한 원본에서 노드 ID·비용·해금·효과·연결 관계와 스킬 규칙을 대조한다. 출처·버전·확인 날짜를 남긴다. 확인되지 않은 규칙은 보류한다.
3. 검증된 카탈로그 후보로 경로 연결, 포인트 비용, 스킬 보너스, 기존 저장 배분의 호환성을 로컬에서 확인한다. 이름만 바뀐 경우와 계산이 바뀐 경우를 따로 검토한다.
4. 읽기 전용 교차 리뷰를 거쳐 기존 관리자 카탈로그 수정 경로로 검증된 데이터만 반영한다. 기존 인증·권한·CSRF 조건을 그대로 사용한다. 검토 상태를 없애기 위해 미검증 원본을 덮어쓰지 않는다.
5. 반영 후 카탈로그와 기존 저장 빌드를 다시 확인한다. 다음 정상 원본 확인에서도 규칙 차이가 없으면 해당 원본 변경의 검토 표시가 해제되는지 확인한다. 다른 변경에 대한 reviewRequired는 그 검토까지 완료하기 전 임의로 지우지 않는다.

사용자 화면에는 마지막 검증 데이터를 쓰고 있음을 알리고 직접 수정한 배분을 유지한다. 이번 작업은 검토 상태와 보수적인 반영 경계를 추가한 것이며, 원본 규칙을 자동 승인하는 관리 기능은 추가하지 않는다.
